# 예약 브리핑 검증 — 2026-10-19

## 결론
현재 코드만으로는 “ChatGPT 예약이 정시에 실행되어 일정·업무 브리핑이 웹페이지에 자동 표시된다”는 요구를 충족했다고 판단할 수 없습니다.

## 검증 범위
- 실제 로컬 HTTP 서버, 데모 저장소, Chrome의 390×844 모바일 뷰포트.
- 일정 생성·수정, 업무 주제와 할 일, MCP/Actions 인증 경로, 저장 후 API 조회, 화면 표시.
- 테스트 스크립트가 외부 작성자를 대신하여 지연 후 고정된 테스트 문구를 저장했습니다. AI 생성이나 실제 ChatGPT 예약 실행이 아닙니다.
- 실제 iPhone/Safari, 푸시 알림, iCloud/Google 실계정, Vercel 운영 환경, ChatGPT Scheduled 실행은 검증하지 않았습니다.

## 발견 사항
1. `prepare_chatgpt_schedule`은 `request_only`와 프롬프트를 반환합니다. 실제 예약 등록·예약 ID·다음 실행 시각·실행 성공 여부를 확인하는 구현이 없습니다.
2. `public/assistant.js:25`는 일간·주간 요청 모두 `save_daily_briefing`만 지시합니다. 업무 내용을 요청해도 Workstream 저장 도구 `save_briefing` 호출 지시가 없습니다.
3. Custom GPT Actions 스키마에는 일간 저장 경로만 있습니다. Workstream 저장은 MCP 경로로 가능합니다. Actions만 연결한 구성에서는 업무 카드에 저장할 수 없습니다.
4. `public/app.js:1299`는 Workstream 화면의 업무 노트만 60초마다 확인합니다. 일정 노트는 자동 조회하지 않습니다. 기존 일정 노트가 있으면 종 버튼도 서버에서 다시 읽지 않아 오래된 내용을 보여줍니다(`:1667`).
5. 휴대폰 앱으로 돌아올 때 새로고침은 백그라운드에 30초 넘게 머문 경우에만 수행합니다(`:1689`). 웹 서비스워커에는 예약 실행/백그라운드 브리핑/푸시 구현이 없습니다.
6. iCloud 자격 증명이 없으면 `config.demo`가 활성화되고 노트는 메모리 데모 저장소에 저장됩니다. Google Calendar만 설정한 배포에서는 브리핑 영속 저장을 별도로 검증·구현해야 합니다.
7. 일회 알림 요청은 ChatGPT 알림 문구만 생성하며 웹앱으로 결과를 저장하라는 지시가 없습니다. 일회 알림이 웹페이지에도 뜨는 기능으로 볼 수 없습니다.
8. 실행 이력, 실패 재시도, 마지막 성공·실패, 예약 예정 시각에 대한 웹앱 표시가 없습니다. 정시 시작과 브리핑 작성 완료는 구분해야 합니다.

## 권장 후속 작업
- 일정·업무 각각 저장할 도구와 실패 처리 지침을 예약 요청에 명시.
- 일정·업무 브리핑 자동 조회, 첫 노트 도착과 모바일 복귀 시 새로고침 처리.
- 예약 실행 기록, 실패 상태, 재시도와 중복 방지 도입.
- 인터넷에서 접근 가능한 Vercel 배포 후 ChatGPT에 실제 도구 연결. 일간·업무 테스트 예약을 짧은 간격으로 실행하고, 휴대폰을 잠근 동안 실행 기록과 저장 시각을 확인.
- 정확한 완료 시각이 핵심 요구라면 외부 실행 환경의 스케줄러에서 생성·저장을 관리하는 구조도 검토.

공식 문서: https://learn.chatgpt.com/docs/automations , https://developers.openai.com/training/walkthroughs/scheduled-tasks
클라우드에서 연결 도구만 사용하는 예약과 로컬 컴퓨터가 필요한 예약을 구분합니다. 현재 계정에서 Vesper MCP가 예약 실행에 실제 사용 가능한지는 배포 후 확인해야 합니다. 문서로 특정 정각 완료를 보장할 수는 없습니다.

애플리케이션 원본 소스는 변경하지 않았습니다. 추가 파일은 테스트 스크립트와 이 보고서·결과·스크린샷입니다.
